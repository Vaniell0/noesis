## H25. WKV state is a learnable computational substrate for approximate linear algebra without CoT tokens
### *(wager, Phase 3, post-RL)*

**Claim.** A model trained via RL can learn to encode equation coefficients as rank-1 WKV
updates during think-span tokens, then read them back via attention at the answer token to
produce approximate numerical solutions — without writing intermediate steps to the visible
output stream. Accuracy scales with model size (larger head_size × n_head → higher-precision
rank-1 decompositions, less interference between stored rows).

**Motivation.** WKV state capacity for G1i: `32 heads × 64 × 64 × 32 layers` ≈ 8 MB at
bf16. A single 64×64 matrix occupies 32 KB; the state fits ~250 such matrices. Capacity is
not the bottleneck. The bottleneck is *controllability*: the model must learn to generate
tokens whose v/k projections write numerically structured content into state rather than
purely semantic content. External correspondence (2026-08-16) reported state-dependent
stopping and multi-step symbolic composition on G1h 7.2B using frozen backbone + one-layer
adapter, with causal controls (swap/replace/zero) ruling out token-surface confounds.
That result is boolean/symbolic; H25 is the numerical extension of the same mechanism.

**Why this matters vs. transformers.** A transformer can do in-context arithmetic only via
chain-of-thought (visible tokens, output-budget-limited) or weight memorisation (no
generalisation). WKV state accumulates across tokens invisibly: think-tokens write,
answer-token reads, no CoT emitted. The computation is invisible to the output stream, does
not consume the response token budget, and generalises to coefficient values not seen during
training (if the rank-1 write mechanism is learned as a skill, not a lookup).

**ROSA's role.** WKV rank-1 writes are approximate: bf16 limits precision to ~3 significant
decimal digits, and learned time-decay `w` attenuates earlier writes before the full matrix
is assembled. ROSA (RWKV-8) eliminates both limitations: its rank-1 outer product writes are
exact (no approximation, no decay interference on the write channel), and the suffix-automaton
read is exact-match rather than soft-attention. In a full RWKV-8 system: WKV handles semantic
routing (understand what equation to solve), ROSA stores exact coefficient values, WKV reads
the result — a complete numerical pipeline with no external calls.

**Structural prediction.**

| Regime | Mechanism | Precision | Token cost |
|---|---|---|---|
| G1i + RL (this H25) | Learned rank-1 writes | bf16, ~3 digits | 0 output tokens |
| G1i + RL, large model | Same, more heads | Higher | 0 |
| RWKV-8 (ROSA) | Exact rank-1 writes | fp32, exact | 0 |
| Transformer CoT | Pattern + explicit steps | Depends on digits | O(N) tokens |

**Effort-frontier connection.** For mathematical tasks, the K-frontier is predicted to be a
step function: flat for K < rank(equation system), step up once all rows are written, flat
again. Qualitatively different from the smooth curves expected for extraction/symbolic tasks.
If observed post-RL, it confirms K acts as write-budget for matrix rows, not reasoning-trace
length.

**Falsification.**
- Post-RL MLP probe on mathematical prompts shows no increase in nonlinear state content
  vs pre-RL (no new dimensions activated for coefficient structure) ⇒ pattern-matching.
- Accuracy on linear equations with out-of-distribution coefficients does not exceed random
  baseline ⇒ weight memorisation, not state-substrate computation.
- Zeroing L16 WKV state at answer token does not degrade accuracy ⇒ state is not read.

Note: linear IPC is not the right probe here (IPC≈0 baseline, H8). Use MLP probe
(2-layer, 256 hidden) comparing pre-RL vs post-RL state on mathematical prompts.

**Measurement.** Construct held-out set of 2×2 and 3×3 linear systems with integer
coefficients, unique solutions in [-20, 20]. Compare: (1) G1i base, (2) G1i post-RL,
(3) G1i post-RL with WKV state zeroed at answer token. If (2) > (1) and (3) < (2),
state is causally involved. Complementary: MLP probe on mathematical prompts before
and after RL (replaces linear IPC — see H10 section).

**Sharpened framing, 2026-08-23: "WKV as a learnable physical computer"
— why noesis kept failing to name this architecture cleanly.** Not a
world model (Dreamer/RSSM-style — no independent forward dynamics of its
own, see `docs/community-map.md`'s "Latent imagination" entry on exactly
this point) mainly because of the weights: WKV is a hybrid — the
per-channel decay `w`, rank-1 write `v^T k`, and the hidden r/a/g control
signals are architecturally *fixed physics* (the recurrence formula
itself, `docs/rwkv7-mechanics.md`), but which computation that physics
performs is entirely learned (weights choose what to write/read/decay,
not the network topology). "Self-programming recurrent substrate":
training teaches the model to use decay/write/control as computation
primitives, not merely as a memory mechanism — the actual, more precise
restatement of this hypothesis's title.

**Cheap pre-test proposed 2026-08-23, before spending GPU-hours on
fleeb83's full-scale version: build a genuinely micro WKV cell (1 layer,
tiny head_size, CPU-only) and run his counterfactual-altered-recurrence
test where ground truth is fully known analytically, not statistically
inferred.** Since the exact recurrence formula is already derived
(`docs/rwkv7-mechanics.md`), a toy scale lets every claim below be
checked directly against the algebra instead of guessed from probe
output:

1. **Local-Jacobian/curvature sampling, not literal "linear region
   counting."** RWKV-7's r/w/k/v/a/g gates are smooth (sigmoid, softplus,
   tanh), not piecewise-linear like ReLU — there's no hard-boundary
   "region count" the way there is for ReLU networks. The measurable
   analog: sample `∂S_t/∂S_{t-1}` (the local linearization of the update,
   at fixed input) across many different input configurations on the toy
   cell, and look at how much that local Jacobian varies — this is the
   same quantity J-lens/R-lens already approximate on the full model
   (`docs/community-map.md`), just computed exhaustively instead of
   sampled, because the toy scale makes exhaustive tractable.
   **Distinct from, not redundant with, nonlinear IPC**: IPC (MLP probe)
   is a *statistical* capacity measure (how much task-relevant
   information a flexible decoder can extract, given enough data);
   direct Jacobian sampling from the known formula is a *mechanistic*
   characterization (why/how that capacity arises structurally — smooth
   curvature vs. combinatorial switching among near-linear regimes).
   Correlated numbers would still be two independent kinds of evidence,
   not a duplicate measurement.

   **Done, 2026-08-23, in closed form — no numerical differentiation
   needed.** For FIXED controls (r,k,v,w,a_gate), `micro_wkv_step`'s
   update is exactly affine in state (not just locally linear — the
   same operator for every state value): `new_state = A@state + k⊗v`
   with `A = diag(decay) − outer(kk·a_gate, kk)` (rank-1 correction on
   a per-channel-decay diagonal, derived directly from the code, not
   approximated). Sampled `A`'s spectral radius (worst-case long-term
   contraction rate) across 2000 random `(k, w, a_gate)` draws,
   head_size=8: mean 0.9527 (std 0.017, range 0.79-0.97), **zero
   complex eigenvalues in 2000 draws** (no rotation/oscillation from
   erase-rewrite at these parameter ranges), **zero draws with radius
   > 1.0** (erase-rewrite never destabilizes the linear part, at least
   under this sampling). Sharper follow-up: fixed `(k,w)`, swept
   `a_gate` from 0 to 1 uniformly across channels — spectral radius
   moved from 0.9565 to 0.9559, **essentially unchanged across the
   ENTIRE range of a_gate**. Mechanistic reason: `kk` is unit-norm, so
   the rank-1 erase-rewrite correction's reach is confined to that one
   direction — it doesn't touch whichever channel actually holds the
   dominant (largest) decay value, which is what sets the spectral
   radius. **Real, quantitative finding: stability (spectral radius)
   and computation (erase-rewrite, proven necessary by the frozen-
   readout ablation above) are nearly DECOUPLED in this architecture**
   — training can push `a_gate` anywhere needed for the computation
   without risking destabilizing the linear part through this specific
   channel. This closes the original 3-item "Cheap pre-test" plan.
2. **No true time-reversal exists — this is architecture, not an
   oversight.** Decay is a genuine contraction (`retention =
   exp(-exp(w)) < 1` almost everywhere — `docs/rwkv7-mechanics.md`),
   information is really discarded each step; the rank-1 write isn't
   uniquely invertible either. What the toy scale DOES buy: numerically
   solve for the best-achievable approximate pseudo-inverse directly
   (minimize `‖state_after_prompt − update(S, candidate_marker)‖` by
   optimization over `candidate_marker`, not by training a network to
   approximate it) — this gives a **ceiling**, not a mechanism: how close
   ANY marker embedding could possibly get to a rewind target, given the
   fixed algebra. The trained rewind marker (Phase 2's design,
   `docs/rl-track.md` §Track status) can then be benchmarked against this ceiling —
   telling us whether training is leaving real performance on the table
   or already near the mathematical limit.

   **Why this isn't just an engineering gap — the reversible-computing
   contrast (2026-08-23).** Real reversible logic (Toffoli/Fredkin gate
   families, adiabatic circuits) gets its efficiency specifically because
   the gates are *bijective by construction* — no information is erased,
   so no Landauer cost (kT·ln2 per bit) is paid, and the energy that
   would otherwise dissipate as heat can in principle be recovered by
   literally running the computation backward. The toy cell's own
   `verify()` (check #3, item 1 above) already demonstrated the opposite
   property for WKV's delta-rule: the naive undo fails once the
   erase-rewrite term is active, precisely because information is
   genuinely discarded, not reversibly transformed. **This is why a
   rewind marker can only ever be a trained approximation, not a real
   inverse — not an implementation shortfall, a direct consequence of
   the underlying dynamics not being bijective**, the same way no amount
   of clever engineering makes an ordinary (non-reversible) logic gate
   recover its erased input bit. The pseudo-inverse ceiling above is the
   correctly-scoped question given this: not "can we find the exact
   inverse" (provably impossible in general) but "how close can any
   marker get."

   **The linear (non-erase) part of the recurrence, separately —
   worth naming precisely, not just informally.** With `a_gate=0`,
   `state_t = state_{t-1}·decay + k_t⊗v_t` is an ordinary time-varying
   linear dynamical system: `decay≈1` gives pure accumulation
   (`Σ_t k_t⊗v_t`); `decay∈(0,1)` gives exponential smoothing, i.e. a
   per-channel IIR filter; different channels running different decay
   rates gives a bank of filters at different time constants
   ("multiple timescales" — a real, if informal, description of
   per-channel `w`'s role already implicit in this project's decay
   discussion, worth stating in these terms explicitly). This connects
   directly to the reservoir-computing lineage already in
   `docs/community-map.md` (Dambre et al. IPC framing) — classic ESN
   reservoirs are *fixed* random dynamics with only the readout trained;
   RWKV-7's `A_t` (decay), `B_t` (rank-1 write) are *both* generated by
   the model itself, input-dependent, which is a strictly wider class of
   linear operators than a fixed reservoir can express, before the
   (nonlinear) erase-rewrite term is even considered. Branching/
   comparison/argmax-style decisions need genuine nonlinearity the
   isolated cell doesn't have (only `a_gate`'s sigmoid); in the real
   model that nonlinearity comes from the FFN blocks between time-mixing
   layers and from the controller (the r/w/k/v/a/g projections) itself
   being a nonlinear function of the embedding — the recurrence supplies
   the linear/bilinear substrate, decisions are routed in from outside
   it. Real G1i has 32 heads × 32 layers, each head an independent
   head_size×head_size linear/bilinear operator — a large distributed
   computational resource in principle; whether training actually
   organizes it that way is untested, not yet claimed.

item 3's place — not item 3 itself.** What follows (multiplication +

predict-the-exact-output-under-an-altered-formula test item 3 above

Built `experiments/A0_state_probe/micro_wkv.py`, a faithful single-head
RWKV-7 delta-rule cell (verified against three properties from
`docs/rwkv7-mechanics.md`: zero-state reduction to a pure write,
retention floor ~0.5452 uncapped toward 1, non-invertibility once the
erase/rewrite term is active — the second check's first draft had the
floor/ceiling direction backwards, caught by running it, the same
exp(w)-vs-exp(-exp(w)) trap this project already fell into once for
real). A small MLP controller was trained end-to-end to drive the cell

linear superposition of two independent writes, no dependence on the
recurrence's own nonlinear mechanisms, so it doesn't discriminate
anything).

**First design mistake, caught by the user immediately: the controller
saw BOTH `a` and `b` at every single step** (`ab = stack([a,b])`
computed once, fed unchanged into every step's control generator). This
completely undermines any claim about the recurrence: the controller had
no need to rely on the state to carry anything forward in time, since it
had direct, un-mediated access to both operands throughout — the
apparently clean result below (held-out R²=1.0000 linear decodability of
`a`, `b`, AND `a·b` from final state, verified with a proper 1600/400
train/test split after first catching an in-sample-overfitting version
of the same check — the exact IPC-methodology trap already documented in
`docs/community-map.md`) does NOT establish that the *recurrence*
performed the multiplication. It only shows the controller MLP *can*
compute `a·b` (unsurprising — MLPs approximate smooth bilinear functions
easily) and dump the result into a state slot for the readout to find.

**Corrected design: `a` revealed only at step 0, `b` only at the final
step, two genuinely blank steps in between (constant zero input,
independent of `a`/`b`'s actual values) — forcing the state to carry `a`
across time with no side channel.** This trains successfully too
(in-distribution R²=0.9996, held-out-range R²=0.9239) — real evidence
the recurrence CAN carry a continuous value across multiple steps and
combine it nonlinearly with information arriving later, which is
already a nontrivial, useful result on its own.

**Second finding, from the a_gate counterfactual ablation the user
specified (fix `a_gate` to 0 or 1 at inference, check whether the output
degrades in a way that implicates the delta-rule mechanism specifically)
— surprising, and it complicates the strong reading of H25 further, not
confirms it.** On the *flawed* (sees-everything) model, forcing
`a_gate=0` (erase/rewrite term off) dropped R² from 0.9989 to 0.4037 —
suggestive, but confounded, since `k`/`v` themselves could already
encode `a·b`-relevant nonlinearity independent of the erase/rewrite term
(they're also functions of both operands at every step in that flawed
version). **On the corrected, staged model — the clean test — the same
ablation barely mattered: `a_gate=0` gave R²=0.8364, `a_gate=1` gave
R²=0.9516, both close to the unablated 0.9996.** The delta-rule
erase/rewrite mechanism specifically is *not* what this trained
controller relies on. Working out why, mechanistically (not yet fully
verified, but consistent with the algebra): with `a_gate=0`, the update
is `state = state·decay + k⊗v`, a purely linear memory, and the readout
itself (`out = r @ state`) is *already* a bilinear operation between the
current step's `r` (a function of `b`, at the final step) and the
accumulated state (a function of `a`, decayed) — `Σ_i r_i(b)·decay_i(b)·
state_before[i,j](a)` is a genuine `a×b` interaction, entirely through
the ordinary read/decay path, no erase-rewrite required. **If this holds
up, it means RWKV-7 has (at least) two distinct loci where a multiply-
like temporal interaction can arise — the delta-rule erase/rewrite term,
and the readout's own bilinearity between the current step's `r`/decay
and the accumulated state — and this experiment's trained controller
preferred the second, not the specific mechanism H25's strong framing
(and fleeb83's own framing) was asking about.**

**Third finding, same night, the decisive one: freezing `r` and `w` at
the final step to constants independent of `b` (`FrozenFinalReadoutController`
in `experiments/A0_state_probe/micro_wkv.py`) closes the readout-bilinearity
shortcut entirely — any surviving `a·b` computation must route through
`k`/`v`/`a_gate` (the write and erase-rewrite terms) instead, since `r`
and `decay` can no longer vary with `b`.** Result: the model still
solves multiplication cleanly (in-distribution R²=0.9998, held-out(OOD)
R²=0.8361). Then, forcing `a_gate=0` **on top of** the frozen readout —
closing the erase-rewrite path too, with no shortcut left open —
**collapses performance to R²=-0.0810, worse than predicting the mean.**
This is the clean, unconfounded version of fleeb83's test: with every
alternative path closed off, the delta-rule erase/rewrite mechanism is
not merely available, it is **necessary**. The recurrence's own physics
is doing real, load-bearing computational work here, not just serving
as a wire between an omniscient controller and a readout.

**Where this actually leaves H25, honestly, after all three passes:**
the toy scale now has a genuine, controlled, positive demonstration of
the mechanism H25 is about — WKV's specific delta-rule erase/rewrite
term can perform a real bilinear computation (multiplication) across a
temporal gap, and does so necessarily once the simpler readout-bilinearity
shortcut is closed off. This is stronger support for the "physical
computer" framing than the first (confounded) or second (shortcut-available)
passes gave, precisely because it survived two rounds of the user finding
real holes in the experiment before accepting the result. Still toy-scale,
still single-task, still not evidence about the real ThinkChain model —
see the scope limit below — but no longer "probably just readout
bilinearity"; both mechanisms are real and this task can be forced to
rely on either one. `stable_rank` staying near 1.0 throughout all three
passes remains worth keeping as a general lesson independent of
everything else: spectral energy concentration and linear decodability
are dissociable measures, a near-rank-1 state is not necessarily
information-poor.

**Fourth finding, same night: "reproduce fleeb83, but on exact
operations" (`ChainedController`, `experiments/A0_state_probe/micro_wkv.py`).**
fleeb83's own reported result (G1h 7.2B, frozen backbone + trained state
interface) isn't just "carry a value" — it's operand AND operation
selection held in state, one result written back and used to select/
feed the NEXT operation, chained to depths 4/8/16/32, 48/48 correct,
Boolean/symbolic. Built the continuous-arithmetic analog: round 0 loads
an initial operand; each subsequent round reveals one (operand, op_code)
pair (op_code ∈ {add, multiply}) and the controller must combine
whatever the state currently holds with that operand according to the
selected op — never seeing the running total directly, only through
state, same discipline as the staged multiply experiment. At a 2-operation
chain (3 rounds): **in-distribution R²=0.9980, consistent across all
four op-combinations** (add→add 0.9960, add→mul 0.9987, mul→add 0.9977,
mul→mul 0.9992) — genuine operation-selection-and-chaining from state,
not a memorized single path. **Held-out(OOD)-range R²≈0.58-0.60** —
markedly weaker generalization than the single-multiply task's ~0.83-0.92,
consistent with error compounding across two chained nonlinear steps;
reported honestly, not smoothed over. Depths beyond 2 operations, and
fleeb83's own state-dependent-stopping property (mapped conceptually
onto this project's existing dynamic-phase-stop mechanism in
`train_think_distill.py`, not yet built into this toy chain), are not
attempted yet.

**Seventh, same night: the pseudo-inverse ceiling, item 2 from this
section's original plan, run** (`pseudo_inverse_ceiling()`,
`experiments/A0_state_probe/micro_wkv.py`). Directly optimizes the raw
physical controls (r,k,v,w,a_gate) — not a trained embedding-generating
network, a strictly more expressive upper bound on what any real Phase
2 rewind marker could achieve — to pull a state back toward its origin
after drift, repeated over T ticks (same repeated-constant-embedding
mechanic as real markers). Setup: a reference origin state, drifted by
4 random "explore" ticks to 146.5% relative distance
(`‖S1−S0‖/‖S0‖`). Results: **T=1 tick → 75.7% relative error, T=4 →
58.3%, T=8 → 55.8%** — real, substantial improvement over doing

non-invertibility established earlier in this section. Design
takeaway for Phase 2: don't expect a trained rewind marker to fully
reset state — expect roughly half the drift to remain even in the
