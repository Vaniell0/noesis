## H10. The frontier acc(M): time in the state buys accuracy only where one pass is not enough

Rewritten 2026-11-11. Notation is the frame's (`hypotheses/README.md` §2): `M` ticks before the
answer, each feeding the model's own last-layer vector back; `acc(M; F)` greedy accuracy on a family
`F`. The file was first written for a three-knob design (re-reading `N`, emitted tokens `K`, readout
mode); that design is retired and kept in §4 as a record.

### 1. Statement

**Claim.** After training for it, on a task family that one pass cannot solve, the same checkpoint
answers more items at some `M ≥ 2` than at `M = 0`. On families one pass can solve, `acc(M)` is flat
in `M`: the ticks are a pass-through.

*One pass cannot solve `F`* is defined operationally: an arm trained on the same teacher data with
`M = 0` (the control) stays below the target on `F`. Without the control, a gain at `M > 0` cannot be
told from a gain in the direct path.

**Estimator.** Per family, on one checkpoint, paired by item: items right only with ticks against
items right only at `M = 0` (McNemar), and the ticks arm against the `M = 0` control trained on the
same data. Beside it, the curve `acc(M)` for `M = 0..8` and the spread of the fed latent over ticks
(`H25.md` §4).

**Refuter.** On a family that qualifies, after training for it, `M = 0` of the same checkpoint is not
worse (paired gain below 5 points or McNemar `p ≥ 0.05`), or the `M = 0` control matches the ticks
arm.

### 2. What bounds the frontier

From the setup (frame §3, `H25.md` §1):

- *Data processing.* Ticks raise usable information, never information. A fact absent from the input
  and the weights stays out of reach at any `M`.
- *Tick lemma.* If the controls stop changing, a tick contracts at rate `ρ(A)` to a rank-1 fixed point:
  `acc(M)` can change only before the loop settles, and what earlier input left in the state fades at
  the same rate.
- *Open-loop lemma.* In a cell whose controls do not read the state, silent steps do not widen the
  set of computable functions. The real model is closed, so a rising frontier has to come from ticks
  whose fed latent keeps changing the controls: a different operator at each tick.

Regular (frame §3): an output-level loss is lowered more cheaply by repairing the one-pass read than
by computing in the ticks, whenever one pass plus the answer's tokens suffice.

So a rising frontier needs two things at once: a family one pass cannot solve, and ticks that keep
moving (spread across prompts kept, step size not near zero from tick 1). A measured instance of the
second: repeating one constant marker converges within about four ticks (`delta_cos_prev` → 0.997),
while switching to a new marker turns the direction almost orthogonally (0.097)
(`docs/phase15-gap-matrix.md`). Distinct inputs give distinct operators; repeats settle.

### 3. Measured

**Untrained models.**

- G1i 2.9B base, 48 tasks of the old rubric set: self-feed loop with sampled tokens, `M_max` 16,
  12.5% (6/48) (`experiments/_common/results/m_axis_eval_g1i.json`); the same tasks read once with a
  32-token readout, 33.3% (16/48) (`experiments/A0_eval/results/h10_state_readout_g1i_base.json`).
  Different modes, not a paired comparison.
- The plain model does not use extra time (`HZLK.md` evidence): re-reading the question 0.469 against
  0.531 for answering at once (32 patterns), 0.062 against 0.062 on arithmetic; 2 and 8 ticks of its
  own expected embedding 0.344.
- Emitted-token budget on an early fine-tune (`step4_merged`, 2026-08-05): `K` = 0 gives 0/48, `K` =
  128, 512, 2048 give 4/48 each (`docs/effort-frontier.md`).

**Trained for ticks** (`HZLK.md` §6; `experiments/rl/results/s1_pilot_g1d04b/`,
`experiments/rl/results/qwen35_08b/`):

| model and training | items | ticks | `M = 0`, same checkpoint | only ticks / only `M = 0` | reading |
|---|---|---|---|---|---|
| G1d 0.4B, CE, one tick | 304 plain | 75 (`M = 1`) | 73 | the same 30 new items on both paths | pass-through |
| G1d 0.4B, KL T=2, `M = 4` | 304 plain | 44 | 46 | 2 need the ticks, both format rescues | pass-through |
| G1d 0.4B, privileged-hint distillation | 289 eval | 75 | 81 | 6 / 12 | pass-through; two-hop items 0-2 of 120 |

Shape over `M`: the KL `M = 4` model is flat over `M = 1..8` (8-10 of 72) and its fed latent sits at a
per-prompt fixed point from tick 1 (cosine 0.999-1.0); the KL model trained on one tick falls to 0 by
`M = 8`. After training, latent noise up to twice the latent's norm flips 1 of 40 answers: the answer
barely depends on what the ticks carry.

Every family tested so far is one that one pass solves after distillation (the `M = 0` controls reach
or pass the ticks arms). The families meant to qualify, ciphers, have no teacher: on Qwen3.5 0.8B,
0 of 585, 0 of 240 and 0 of 60 at `M = 0`, its own chain of thought 0 of 24, and one epoch of CE on the
plaintext does not teach the table lookup.

Toy: parity with silent steps is withdrawn as evidence (`H25.md` §2): open-loop cell, one seed.

**Status.** The refuter holds on every trained checkpoint, on families that do not qualify. The
statement itself is untested: no qualifying family with a teacher exists yet.

### 4. Record: the retired three-knob design

`K` emitted reasoning tokens, and the readout mode (`silent`, `prompt_cot`, `state_readout`), with a
non-trivial Pareto frontier on the old 48-task rubric set. Retired because re-reading is not an axis
(the loop prefills once), `K` is the emitted chain of thought, and the readout mode named where `K`'s
tokens came from. Its three registered refuters (the default cell dominant; readout equal to silent;
accuracy falling with `N`) belong to that design. The third fired on the checkpoint below (`N = 3`).

### 5. Side records

Kept as data; each bears on what the loop has to work with.

- *Context length against chunking.* Step 9b trained at `ctx_len` 512 left fewer than three chunks per
  sequence, so the state loss never fired; extraction fell 62.5% → 12.5%. `ctx_len` and `chunk_ctx` are
  independent settings.
- *Entropy of the target* (external, Scarletwolf 2026-08-07): reasoning tokens help where the answer
  is not yet constrained by the context and hurt where it is (tool selection 71 → 58).
- *Stored but not read* (external, icophy 2026-08-12): the base model's codebook decoding and the
  fine-tuned bit-substitution solve are one mechanism at different budgets; fine-tuning moved the read
  path, the state still holds the codebook. This is the fact class "stored, not read" of the frame.
- *Narrow-casting* (icophy 2026-08-13): after enough prior successes in one context the model commits to
  the most recently used pattern (two tracks, one fact deep: 65% → 25% after step 7); fresh sessions of
  the same length do not collapse, so it is a context attractor, not saturation.
- *Multi-turn* (Scarletwolf 2026-08-12): multi-step tasks 0 of 2 for every model measured; a trained state
  installs dispositions (when to act, when to abstain), not procedures.
- *Readout by re-asking* (BlinkDL 2026-08-12): asking the model to repeat after prefill recovers what the
  state holds, without training.
- *Tokenizer position asymmetry* (2026-08-14): in grids the same letter gets a different token at column
  0, at later columns and after a newline; word search is 0 of 56 on G1i and G1h at every scale.
- *Linear decodability (IPC)*: held-out linear IPC on G1i 2.9B base about 0 past L0
  (`experiments/A0_state_probe/results/ipc_g1i_fixed.json`, 256 tokens), but 5.06 / 15.17 / 15.31 / 15.01 /
  14.23 of 16 at L0 / 4 / 8 / 16 / 23 on G1d 0.4B through the same pipeline
  (`experiments/_common/results/adhoc/ipc.json`); a correspondent's numbers (512 tokens, method unclear)
  give 17-26% of the ceiling natively and 46.5-47.8% for every model on one shared 1024-token trajectory.
  Not reconciled; current values are in the frame under H8. On the Xyra lineage the last layer's IPC
  goes 0.972 → 0.643 → 3.163 from base through two training stages: deep layers join late.
