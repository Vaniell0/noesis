## H26. The optimizer's geometry selects which internal mechanism a trained solution uses — and for a recurrent-state model, the right metric is induced by the state, not fixed in advance

### *(wager, cross-cutting: bears on every training decision in the RL track)*

**Claim, weak version.** For a fixed architecture and task, the choice of optimizer — more
precisely, the norm geometry its update rule implies — selects *which* internal mechanism a
trained solution relies on, among mechanisms that are equally accurate. Accuracy does not
identify the solution; the optimizer does.

**Claim, strong version — reframed 2026-09-13 (this replaces an earlier, weaker
formulation; see "What this claim used to say" below).** Optimizers do not differ only in
*which* solution they find — they play **different roles at different stages**. A
geometry-shaping update rule (Muon's orthogonalized, spectral-norm step is the instance we
have) **builds** the state's spectral structure during pretraining; a coordinate-wise
adaptive rule (Adam) **bakes** it — specialising within a structure it leaves intact. The
interesting object is therefore neither optimizer alone but a procedure that **builds the
geometry together with the mechanism that consumes it** (the M chain), which is something
neither pure optimizer does and which has a directly measurable signature: it should
*increase* the number of live directions the state carries, where Adam demonstrably does not
move that number at all.

**Why this is one hypothesis and not two.** The weak version is what *happens* (measured);
the strong version is *why*, and it predicts the weak one. If different update geometries
build versus preserve structure, then two optimizers reaching the same accuracy must be
arriving with different internal mechanisms — which is exactly the 10-seed result.

**What this claim used to say, and why it changed.** The first version of this file argued
that every fixed norm — Muon's spectral norm included — is *mismatched* to the state's own
geometry, and that the mismatch explains fine-tuning collapse. The first measurement
(2026-09-13, evidence log) went the other way: Muon turned out to be the better-behaved
optimizer in state terms, not the mismatched one. Combined with the same day's spectral
measurements (Adam LoRA fine-tuning leaves breadth untouched; the pretraining that produced
that breadth was Muon's), the build/bake framing fits the data the mismatch framing did not.
The earlier formulation is recorded here rather than deleted because the mismatch prediction
was pre-registered, tested, and did not survive — which is the point of keeping the log.

**What this says about the 2.9B collapse — a mechanism, not a restatement.** Fine-tuning a
model with a geometry-*re*shaping optimizer, when its geometry is already committed and every
downstream weight is tuned to it, breaks the **coupling** between the two, not the optimizer.
That predicts damage should scale with how thoroughly baked the checkpoint is, and the
existing runs are weakly consistent: the clean-lineage checkpoint (no Adam anywhere in its
history) destabilised *later* — around step 90 — while Adam-continued checkpoints collapsed
almost immediately (`docs/phase15-gap-matrix.md`). Weakly, because those runs differ in more
than one variable; this is a reading the data does not contradict, not a result.

**Motivation — why this is an architecture question here and not a training-efficiency
question.** For a transformer, weights are the model and the KV-cache is storage; picking an
optimizer is a question about how fast you converge. For RWKV-7 the WKV state is where the
computation happens (H8, H25), so *which mechanism the solution uses* is the product, not an
implementation detail of reaching an accuracy number. If the optimizer selects the mechanism,
then the optimizer is a design decision about what the model will be. This reframes the
question the RL track has been asking. "Which optimizer is better" has no answer at matched
accuracy — the honest question is "which mechanism do we want, and which geometry selects it."

**The structural argument for the strong version.** RWKV-7's state evolves as

    S_t = S_{t-1} · (diag(w_t) - k_t k_t^T a_t) + v_t k_t^T

— a decay, a rank-1 erase, a rank-1 write. Not all of matrix space is reachable or meaningful;
the reachable set is shaped by the delta-rule dynamics. This project's own measurements agree:
`stable_rank` on the base model is ~1.15-1.30 (near rank-1, nearly all update energy in one
direction) and held-out linear IPC is ~0 past L0 (the state encodes nonlinearly, it is not a
buffer). The state therefore occupies a narrow, structured region reached by rank-1
increments — a manifold in the informal sense.

An optimizer step moves the weight matrices that *generate* r/k/v/w/a, and so changes which
state trajectories the model can produce at all. There is no reason for "unit step in the
optimizer's norm" and "displacement of the state trajectory" to be proportional: the
recurrence compounds a weight perturbation over T steps, so the amplification depends on where
in weight space you are and on what the state is currently doing. A step that is unit-sized by
spectral norm can be negligible or destructive in state-trajectory terms.

**Relation to existing work in this project.** `L_state` (trajectory regularization) is the
same intuition implemented as a *loss term*, and its failure modes are the failure modes of
that choice: it competes with CE (it dominated CE outright at step 300 in
`docs/verdicts/2026-08-04-a1-pilot-step3-step4.md`), it saturates its clamp and silently
becomes a zero-gradient no-op (observed 2026-09-10 on the step9b corpus, pinned at -10.0 from
step 0), and it is exploitable like any reward term. The strong version of this hypothesis is
the same intuition implemented as a *constraint on the step* instead: the objective is left
alone, only the metric in which it is descended changes. That cannot out-argue the task loss
and cannot be reward-hacked in the same way. If the strong version holds, it is a better
implementation of what `L_state` was reaching for.

**Named prior art for the strong version** (so this is not reinvented under a new name):
natural gradient (Amari) makes the metric a function of the parameters via the Fisher
information — the canonical case of "the model's own geometry determines the step." Riemannian
optimization on matrix manifolds (Absil/Mahony/Sepulchre) moves along geodesics with
retractions back onto the manifold. Unitary/orthogonal RNNs constrain the recurrent matrix to
the Stiefel manifold specifically so the recurrence does not destroy gradient flow — the
closest existing instance of "train in a manifold without destroying it." Muon sits partway:
architecture-aware (it knows a matrix is a matrix) but state-blind (nothing about the WKV
trajectory enters `_muon_update`; the normalization is a function of the gradient's own
singular values, and the norm is fixed for every matrix at every moment of training).

**Falsification.** Pre-registered before the first measurement, per this directory's own rule.

- *Weak version.* Refuted if, across at least three structurally distinct toy tasks, Adam- and
  Muon-trained models matched on held-out accuracy show mechanism-ablation profiles whose
  per-seed distributions overlap (>=5 seeds each, overlapping 90% intervals).
- *Strong version, premise.* Refuted if induced state-trajectory displacement turns out to be
  well predicted by a fixed weight-space norm — |corr| >= 0.9 between induced ||dS|| and one of
  ||dW||_spec, ||dW||_F, ||dW||_inf across training. If some existing fixed norm already tracks
  state motion, there is nothing for a state-induced metric to fix.
- *Strong version, confound.* Refuted if a mid-training optimizer switch produces no
  discontinuity in mechanism signature beyond what an LR-matched change under the *same*
  optimizer produces. This is the obvious alternative explanation for everything observed at
  2.9B — that the step size was simply too large — and it must be controlled, not assumed away.
- *Strong version, practical.* Refuted if a state-displacement-normalized step rule,
  implemented at toy scale, fails to improve the stability of a mid-training optimizer switch
  relative to the same switch under the optimizer's native norm.

**Not a refutation:** "both optimizers reach the same accuracy." That is the hypothesis's
premise, not a counterexample to it.

**Measurement.** The first experiment is deliberately the cheapest one that can discriminate,
and it runs on CPU in minutes — no GPU, no rented VM, no 2.9B checkpoint. Using the existing
`FrozenFinalReadoutController` substrate from H25 (`experiments/A0_state_probe/micro_wkv.py`,
whose `forward` already returns a full `state_trace`), at intervals during training record
both halves of the suspected mismatch:

1. what the optimizer *believes* the step size is, in its own norm — spectral for Muon
   (constant by construction), max-coordinate for Adam (also near-constant by construction),
   with Frobenius as a neutral third reference;
2. what the state trajectory *actually did* — the induced displacement
   `mean_t ||S_t(W_new) - S_t(W_old)||_F` on a fixed, frozen probe batch.

The discriminating quantity is the variability of the ratio between them, and the correlation
between induced displacement and each candidate fixed norm. The strong version predicts that
no fixed weight-space norm tracks state displacement well; its premise-refutation criterion
above is exactly the opposite outcome, stated in advance.

*Two measurement caveats, recorded before the first result so they cannot be mistaken for
post-hoc rescue.* (1) Both quantities drift over training — gradients shrink as the loss
converges, the state's own magnitude changes — so a shared time trend can inflate the
correlation between them without any step-to-step predictive relationship. This biases the
pre-registered criterion **against** the hypothesis (spurious correlation makes refutation
easier), which is the safe direction, so the criterion stands as written; the ratio's
coefficient of variation is reported alongside it as the less trend-sensitive statistic.
(2) The probe must attribute the state displacement only to the weights whose update norm is
measured: the toy model's non-matrix parameters (step embedding, readout, the frozen final
`r`/`w`) are optimized by a separate auxiliary AdamW in both arms, and if the state trace is
sampled after that auxiliary step, part of the observed displacement comes from parameters
that never enter `dW`. The probe therefore samples between the two steps.

Later rungs, only if the first one survives: (b) normalize the step by induced state
displacement rather than by a weight norm — a trust region in state space instead of weight
space; (c) a genuine Riemannian preconditioner with the metric pulled back from the state
manifold. Both are defined and testable at 50M scale, and neither is tractable at 2.9B on
current hardware.

**First result, 2026-09-13, and what it did to this file's own story.** The premise test ran
and the premise survived its pre-registered criterion (0.731 < 0.9): no fixed weight-space
norm predicts how far the state trajectory moves. The precise positive finding is that under
Muon — whose step is constant in its own norm by construction — the state still moves by
varying amounts that correlate with nothing measurable in weight space. But the same run
contradicts the *narrative* this file was written around. Muon turned out to be the
better-behaved optimizer in state terms, not the mismatched one (CV of induced displacement
0.234 vs Adam's 0.848), and its residual variability is modest rather than dramatic. The
suspicion that Muon's spectral norm is what rips the state is not supported at this scale.

Equally important, at T=4 there is almost no recurrence compounding, and compounding is the
entire mechanism by which a weight step is supposed to become an outsized state displacement.
So this result **cannot** carry the 2.9B collapse story, and should not be cited as if it did.
The next test is a sequence-length sweep: if the decoupling grows with T, the mechanism is
what the hypothesis says and the toy was simply too shallow to show it; if it stays flat, the
strong version loses its main motivation and the 2.9B collapse needs a different explanation
(step size, scale, or the lineage/data confounds catalogued in `docs/phase15-gap-matrix.md`).

**Status.** Weak version: PARTIAL — real, reproducible, 10-seed evidence on one task, and
independent support from the optimizer-implicit-bias literature for the underlying "different
optimizers find different solutions" premise. Its own refutation criterion (three distinct
tasks) has not been run. Strong version: untested, prior 0.4, and the `prior` field above
refers to it specifically — the weak version's prior would be contaminated by the evidence
that already exists.

**Bias to guard, stated plainly.** This hypothesis is attractive because it retroactively
explains a long, confusing session of failed 2.9B fine-tuning runs. That is exactly the
condition under which a wrong explanation feels most convincing. The honest test is the cheap
toy-scale measurement with its LR-matched control, not more 2.9B runs — and the LR confound is
listed above as a refutation criterion precisely so it cannot be quietly dropped later.
