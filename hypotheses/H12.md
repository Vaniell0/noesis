## H12. Working memory is bounded by interference between keys, not by the size of the state

Rewritten 2026-11-11. The question was first asked as "width or decay": how many distinct items
the state can hold at once, against how far back it can reach. The algebra of the step answers part
of it and moves the rest onto the weights. Notation is the frame's (`hypotheses/README.md` §2).

### 1. The state is a matrix trained in context

One step, `S' = S (diag(d) − κ̂ (α ⊙ κ̂)ᵀ) + v k̃ᵀ`. Take the loss `L(S) = ½ ‖S κ̂ − u‖²` of a
linear map that should send the key `κ̂` to the value `u`. One gradient step with rate `η` is

    S − η (S κ̂ − u) κ̂ᵀ = S (I − η κ̂ κ̂ᵀ) + η u κ̂ᵀ.

This is the RWKV-7 step exactly when the retention is 1, the erase gate is the scalar `η` on every
channel, and the write key is parallel to the erase key (`v k̃ᵀ = η u κ̂ᵀ`). RWKV-7 generalises each
of the three: a per-channel rate `α` (an in-context learning rate), retention `d` (weight decay),
and a write key separate from the erase key. So a head's state is a linear map from keys to values,
trained on the context while it is read, and read by `o = S r`: the weights are learned over the
corpus, the state is a small layer learned over one context.

What a linear associative memory of size `n × n` can do follows from linear algebra:

- **Interference.** With pure writes, reading at `κ̂_j` returns `u_j + Σ_{i≠j} (κ̂_i · κ̂_j) u_i`:
  every other stored binding leaks in by the overlap of its key. Only orthogonal keys read back
  exactly, and at most `n` keys are orthogonal.
- **Erase.** The delta step removes what the map currently returns at `κ̂` before writing, so a
  repeated or updated key overwrites instead of piling up; repeated over the bindings it converges to
  the least-squares map, which is exact for up to `n` linearly independent keys.
- **Decay.** Retention below 1 removes a binding at rate `d` per step on the channels it occupies;
  this sets a horizon in tokens.

The size `n × n` is a ceiling. What sets the recall in practice is the overlap of the keys the
weights produce for distinct items, together with decay. Both are properties of the weights, not of
the matrix.

### 2. Claim

**Statement.** Working memory, the number of items a model recalls from its state at once, is bound
by interference between the keys the weights assign to distinct items, well below the size of the
state; decay sets a separate horizon in distance. Training that gives distinct items separable keys
raises working memory without changing the architecture.

**Estimators.**
1. Width: recall at fixed distance as the number of items `N` grows.
2. Horizon: recall at fixed `N` as the distance grows.
3. Separable facts per head against stored pairs (held-out linear probe, n = 400; the estimator of
   `H25.md` §5).
4. Direct: the mean overlap `|κ̂_i · κ̂_j|` of the erase keys written for distinct items in one head,
   which by §1 predicts estimator 3.

**Refuter.** Separable facts per head approach `n`, or keep growing with stored pairs, while width
still falls (the limit is then in the readout, not the storage). Or width is flat in `N` at fixed
distance and recall falls only with distance (decay alone).

### 3. Measured

All on base models unless said; G1d 0.4B unless said.

- **Horizon.** At `N = 16`, recall 0.25, 0.02, 0.03, 0.00 at measured gaps of 60, 229, 472 and
  1000 tokens (n = 30 per cell; `experiments/A0_H12a_working_memory/results-g1d-n30/SUMMARY.txt`;
  0.13 at gap 60 with an adaptive output budget, `results-g1d-n30-adaptive/REPORT.md`). Recall falls
  with distance.
- **Width at fixed gap.** Tail gap 50 words, recall 0.40, 0.40, 0.05, 0.15, 0.05 at `N` = 4, 8, 16,
  32, 64 (n = 10 per cell; `experiments/A0_H12a_working_memory/results-v2/N*.json`): a drop between 8
  and 16, then noise. The v1 width sweep grew the gap with `N` (gap 8 at `N = 4`, 107 at `N = 64`) and
  is not used for width.
- **Floor.** Exact-match accuracy is 0 in every cell of both sweeps and precision is near 0 (the base
  model lists items badly); the v1 run's own verdict was a floor effect. These are recall fractions on
  a task the 0.4B base model does not solve; they give direction, not a capacity number.
- **Parallel tracks** (`experiments/A0_H12b_multislot/`, `results/report_2026-08-07.md`; `K` tracks,
  `P` facts deep, n = 10 per cell). Aggregate accuracy at `K` = 2, 4, 8: G1d 0.4B 18%, 15%, 7%
  (`P = 1` only); G1h 2.9B base 60%, 45%, 26%; G1h 2.9B after action-chain fine-tuning (step 7)
  36%, 32%, 23%, lower than base on 7 of 9 cells, most at `P ≥ 2`.

- **Per head** (G1d 0.4B and G1i 2.9B; files in `H25.md` §5): 12-29 of 64 directions occupied, the
  output depends on about half; 1-2 key→value facts linearly separable, about 3 recalled at 8 stored
  pairs; raising stored pairs from 2 to 8 raises occupancy, not separable facts.
- **Trained for once** (P1 staged recall, `H25.md` §5): the answer narrowed onto fewer directions,
  separable facts fell (7/32 → 3/32): sharpening, not separation.
- **Linear decodability.** Held-out linear IPC ≈ 0 on G1i; the earlier in-sample value (about 12)
  was a ridge-regression artefact.

*Reading.* One head separates 1-2 facts while it has 64 dimensions, and the model as a whole recalls
a handful of items (a drop between 8 and 16 at fixed gap) while it has hundreds of heads: items are spread over heads and share directions in
them. That is what key overlap predicts and what matrix size does not. Decay is measured separately
and is real. The direct estimator (key overlap) has not been run, so interference is the reading
that fits, not yet the measured cause.

### 4. Stored and derivable

A recall limit counts stored bindings. Answers a model can give are more than that: the weights hold
rules from which answers are computed, and a state that holds a relation answers queries about
bindings it never stored. The bound of §2 therefore limits what is held as separate items; it does
not limit what is derived from fewer of them. Fewer stored items per answer also means less
interference, which is why the training stages in `HZLK.md` §6 are judged on separable facts per
head and not on recall alone.

### 5. Retired: a multi-slot state

Proposed 2026-07-22 as the remedy for width: `K` parallel state slots per layer with input-dependent
gating, a learned merge at the readout, and a usage regulariser against collapse onto one slot (the
MoE lesson). Dropped 2026-08-20: heavy engineering without a clear payoff, replaced by ticks and the
exact-recall branch (`HZLK.md` §6). By §1 it adds matrix size, which is not the limit; more slots are
more heads, and the model already has hundreds whose directions items share. It would help only if
the gating gave distinct items distinct keys, which is the claim of §2 by another route. Related work
read for it at the time: RetNet, Griffin, Titans; kernel-based state upscaling (arXiv 2504.05097),
never read in full.
