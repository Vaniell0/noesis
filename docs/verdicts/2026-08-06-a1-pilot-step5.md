## Root cause: format bleeding does not wash out

Every response in both evals is wrapped in `<tool_use>{...}` format. The
model was trained on glaive-function-calling-v2, which is a tool-dispatch
SFT corpus — 100% of responses are tool calls. Training for one epoch (even
with state_reg) entrenches the output format; it does not wash it out.

The step4 prediction in the prior verdict ("theory: format bleeding washes
out at 80%+ epoch") is **refuted**.

Consequences:
- The model cannot produce a direct answer to any task that expects a plain
  string (exact, contains, regex rubrics).
- For `json_subset` tasks, the `input` payload sometimes carries the right
  values under different key names (field-name mismatch is the main remaining
  failure mode).
- More training epochs on this corpus will entrench the format further.

## State_reg signal

State_reg behaved as expected (α=1e-3 is in the active regime; CE ≈ 0.011
equilibrium; clamp reached at step ~200 of Step 4). The signal is real. But
it operates inside the format-bleeding failure: the state carries
tool-dispatch reasoning, not direct-answer reasoning.
