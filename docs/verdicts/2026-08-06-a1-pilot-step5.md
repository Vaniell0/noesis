## Root cause: corpus/eval structural mismatch

**glaive-v2 conversation structure (normalized):**
```
user:         "Decode binary 01001000..."
assistant:    tool_use={name, input}        ← FIRST turn: always a tool call
tool_result:  {...}                          ← environment injects result
assistant:    content="HELLO"               ← SECOND turn: the actual answer
```

**Eval format:**
```
prompt: "User: Decode binary...\nAssistant:"
```
The model sees a first-turn context and generates a tool call — **correct
behaviour per its training**. The second-turn content answer never fires
because there is no tool execution infrastructure.

This is not "format bleeding" from the glaive SFT style — it is the model
doing exactly what it was trained to do. The step4 prediction ("theory:
format bleeding washes out at 80%+ epoch") was based on a wrong mental model:
the multi-turn structure of glaive-v2 is not a formatting quirk, it is the
entire training signal.

**Corpus analysis (2026-08-06):**
- 63,218 rollouts: 100% have `assistant: tool_use` as first turn.
- 25,451 (40%) have first-turn `content` with no `tool_use` — but inspection
  shows these are pre-tool-call phrases ("Of course, let me calculate that
  for you") not reasoned answers. Zero direct-computation examples.
- glaive-v2 is an information-retrieval tool-dispatch corpus. It has no
  direct-reasoning examples regardless of epoch count.

Consequences:
- More training epochs on glaive-v2 cannot fix this — the first-turn tool_use
  is the correct learned behaviour for this corpus.
- Corpus must be replaced (or supplemented) with direct-reasoning examples
  where the model's first turn IS the computed answer.
